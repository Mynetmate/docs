# Network Topology Visualization — สรุปการอัปเดต 04-09-2569

> **สำหรับทีม:** NTV รอบนี้อยู่ในสถานะ Design และ Candidate Contract สำหรับ P2 ต้องรอข้อมูลจาก Device Inventory และ Network Discovery; ยังไม่ใช่ Full-stack implementation

## **ผลลัพธ์–ขอบเขต–สถานะจริง**

หลังจากรายงานความคืบหน้าครั้งที่ 1 และ 2 ผมได้นำแนวคิด Network Topology Visualization มาลดขอบเขตและออกแบบให้พร้อมสำหรับการพัฒนามากขึ้นครับ

เป้าหมายของ NTV คือช่วยให้วิศวกรเห็นว่าอุปกรณ์ใดเชื่อมต่อกับอุปกรณ์ใด ผ่านพอร์ตอะไร โดยสร้างแผนผังจากข้อมูลที่อุปกรณ์รายงานจริง ไม่ใช่ให้ผู้ใช้วาดเส้นตามความเข้าใจเอง

สิ่งที่ผมทำเพิ่มเติมมี 4 ส่วนครับ

1. ผมกำหนดขอบเขตของ NTV รุ่นแรกให้ชัดเจน โดยระบบจะแสดงเฉพาะ Physical หรือ Layer 2 Topology ใช้ข้อมูล LLDP เป็นหลักฐานของการเชื่อมต่อ และใช้ SNMP สำหรับเก็บข้อมูลอุปกรณ์ตามขอบเขตของ Network Discovery ส่วน CDP, Routing Topology เช่น OSPF/BGP และการแสดงผลแบบ Real-time ยังไม่รวมในขอบเขตปัจจุบัน
2. ผมออกแบบการจัดการข้อมูลให้ทุกเส้นเชื่อมตรวจสอบย้อนกลับได้ ระบบจะแยกข้อมูลที่อุปกรณ์รายงานจริงออกจากข้อสรุปที่ใช้แสดงบนแผนผัง สามารถบอกได้ว่า Link มาจากอุปกรณ์ใด พบเมื่อใด และพบจากฝั่งเดียวหรือพบตรงกันทั้งสองฝั่ง หากข้อมูลขัดกัน เก่า หรือยังระบุปลายทางไม่ได้ ระบบจะแสดงคำเตือนแทนการสร้างข้อมูลสมมติ
 3. ผมจัดทำแบบออกแบบสำหรับการพัฒนาต่อ ได้แก่ Database Schema, Component Diagram, Candidate API และ Acceptance Tests พร้อมแยกเจ้าของข้อมูลชัดเจน โดย Device Inventory เป็นเจ้าของข้อมูลอุปกรณ์และพอร์ต Network Discovery เป็นเจ้าของข้อมูล LLDP ส่วน NTV เป็นเจ้าของมุมมองแผนผัง ตำแหน่งอุปกรณ์ และข้อสรุปของ Link จึงไม่เก็บข้อมูลซ้ำกัน
4. ผมลด Feature ที่ยังไม่จำเป็นออกจากรุ่นแรก เช่น การวาดหรือแก้ Link ด้วยมือ การยืนยันหรือปฏิเสธ Link ทีละเส้น Manual Override การแก้ Configuration จากหน้า Topology และการวิเคราะห์ผลกระทบข้ามอุปกรณ์ เพื่อไม่ให้ Scope ขยายเกินเวลาของโครงงาน

**Demo scenario ที่ตั้งไว้คือ** ผู้ใช้เปิดหน้า Topology แล้วเห็นว่า Switch และ Router ที่อยู่ใน Device Inventory เชื่อมต่อกันผ่านพอร์ตใด ข้อมูลมาจาก LLDP และตรวจล่าสุดเมื่อใด จากนั้นสามารถเปิดรายละเอียดและลากจัดตำแหน่งอุปกรณ์บนแผนผังได้

**สถานะปัจจุบัน**  NTV ยังเป็นงานออกแบบและ Candidate Contract ยังไม่ใช่ระบบ Full-stack ที่พัฒนาเสร็จแล้ว และตาม Scope กลางปัจจุบัน NTV อยู่ใน P2 เพราะต้องรอข้อมูลจาก Network Discovery และ Device Inventory ก่อนครับ

ประเด็นที่ผมอยากขอคำแนะนำจากอาจารย์คือ ควรคง NTV เป็นงานออกแบบสำหรับ P2 หรือควรนำเข้ามาทำเป็น Full-stack slice ขนาดเล็กในเทอมนี้ โดยจำกัด Demo เฉพาะการอ่าน LLDP Snapshot แล้วสร้างแผนผังหนึ่งชุดใน Isolated Lab ครับ

หากอาจารย์ถามว่า “แล้วตอนนี้มีอะไรจับต้องได้?” ให้ตอบสั้น ๆ ว่า:

> ตอนนี้สิ่งที่เสร็จคือขอบเขต การแบ่งเจ้าของข้อมูล Schema ความสัมพันธ์ของ Component รูปแบบ API และเกณฑ์ทดสอบครับ ส่วนหน้า Topology และการเชื่อมข้อมูลจริงยังไม่ได้อ้างว่า Implement เสร็จ

หากถามว่า “ทำไมต้องรอ Discovery?”:

> เพราะ NTV ไม่ควรสร้าง Link จากการคาดเดาครับ ต้องรอ Device ID, Interface ID และ LLDP Observation จาก Discovery ก่อน จึงจะแสดงแผนผังที่ตรวจสอบย้อนกลับได้

หากถามว่า “วัดว่าเสร็จอย่างไร?”:

> ทดสอบใน Isolated Lab แล้วระบบต้องแสดงอุปกรณ์และ Link ตรงกับสายที่ต่อจริง ระบุพอร์ตได้ แสดงเวลาที่เก็บข้อมูล และไม่สร้าง Link สมมติเมื่อข้อมูล LLDP ไม่ครบ
