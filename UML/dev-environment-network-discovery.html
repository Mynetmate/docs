UML Deployment & Architecture · MyNetMate Development

Network Discovery Dev Environment

Decoupled 4-tier development architecture: Windows Web UI communicating over HTTP REST to a WSL2 Containerlab Python Backend, delegating discovery to the in-process oxian_py engine using pure SNMP & LLDP MIB crawling across virtual network simulation nodes.

REPOSITORIES & HOST LINKAGE

Repo Decoupling & Ports

  • Mynetmate/mynetmate: Meta workspace code root.
  • Mynetmate/website (Windows): React 19 SPA running on http://localhost:3000.
  • Mynetmate/backend (WSL2): FastAPI container exposing port 8000.
  • oxian / oxian_py: Core discovery package installed as an editable module inside backend.
  • Containerlab (WSL2): Virtual network bridge (clab-mgmt) hosting simulated nodes.

PURE SNMP & LLDP DISCOVERY

oxian_py Execution Flow

  • No ICMP / No Ping: Avoids firewall blocking and unreliable ping sweeps.
  • Step 1 (SNMP Polling): Uses SNMP GET (UDP 161) to retrieve system info (sysName, sysDescr, ifTable) from the seed device.
  • Step 2 (LLDP Neighbor Crawl): Uses SNMP WALK on lldpRemTable (LLDP MIB 1.0.8802) to discover adjacent neighbors and iteratively crawl the topology.

TROUBLESHOOTING GUIDE

Decoupled Failure Isolation

  • UI ↔ API Fail: Verify WSL2 host IP, CORS settings, and FastAPI health (port 8000).
  • Backend ↔ oxian Fail: Check Python editable import, Pydantic request payload, and container logs.
  • oxian ↔ Device Fail: Check SNMP community string (public), UDP port 161 reachability, and LLDP MIB status.
  • Containerlab Fail: Run clab inspect to check container health and virtual bridge links.
