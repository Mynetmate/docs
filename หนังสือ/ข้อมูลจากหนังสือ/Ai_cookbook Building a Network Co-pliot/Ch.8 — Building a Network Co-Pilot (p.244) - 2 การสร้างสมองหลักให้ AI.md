**หัวข้อ 8.2 การสร้างสมองหลักให้ AI (Building the core AI engine)**

หัวข้อนี้สอนการสร้าง "สมอง (Engine)" ให้กับ Co-pilot ของเราครับ สมองที่ว่านี้จะทำหน้าที่รับคำถามจากผู้ใช้, ตีความเจตนา, แนบบริบทของเครือข่ายเข้าไป และให้ AI คืนคำตอบที่มีประโยชน์ที่สุดออกมา

ผู้เขียนอธิบายขั้นตอนการสร้าง Engine (ผ่าน Python Class ที่ชื่อ `NetworkCopilot`) ไว้ 5 ขั้นตอนหลักๆ ดังนี้:

1. **ดักจับเจตนา (Intent Detection):** ฟังก์ชัน `get_intent()` จะคอยแสกนคำที่ผู้ใช้พิมพ์มา เช่น ถ้าเจอคำว่า `configure`, `setup` แปลว่าอยากตั้งค่า แต่ถ้าเจอ `problem`, `down` แปลว่าเครือข่ายมีปัญหา ระบบจะได้รู้ว่าควรโฟกัสไปทิศทางไหน
2. **ดึงข้อมูลอุปกรณ์ (Device Context):** ฟังก์ชัน `get_device_context()` จะทำหน้าที่แสกนหาชื่ออุปกรณ์ในประโยค (เช่น ถ้าพิมพ์คำว่า "R1") ระบบจะวิ่งไปค้นข้อมูลใน Database ทันทีว่า R1 คืออุปกรณ์รุ่นอะไร IP อะไร และตั้งอยู่ที่ไหน แล้วแอบหยิบข้อมูลนี้เตรียมไว้
3. **ดึงข้อมูลเครือข่าย (Network Context):** ฟังก์ชัน `get_network_context()` จะดึงข้อมูลภาพรวม เช่น Topology หรือโปรโตคอลที่บริษัทใช้ (เช่น ถ้าถามเรื่อง OSPF ก็ไปดึงข้อมูล OSPF area ของบริษัทมาเตรียมไว้)
4. **ดึงคู่มือตัวอย่าง (AI Examples):** ระบบจะดึง "ตัวอย่างการตั้งค่าที่ถูกต้อง" (Best Practice) ของบริษัทมาแนบไว้ด้วย เพื่อไม่ให้ AI มั่วคำสั่งเอาเอง
5. **ประกอบร่าง (Prompt Assembly):** ฟังก์ชัน `call_openai()` จะเอาข้อมูลที่ดึงมาทั้งหมดในข้อ 1-4 ยัดรวมกันเข้าไปใน Prompt เบื้องหลัง พร้อมสั่ง AI ว่า _"คุณคือผู้เชี่ยวชาญด้านเครือข่าย จงตอบคำถามโดยอ้างอิงจากข้อมูลอุปกรณ์และตัวอย่างที่แนบมานี้"_

**ผลลัพธ์ที่ได้:** เมื่อผู้ใช้พิมพ์สั้นๆ แค่ _"Configure OSPF on R1"_ AI จะตอบกลับมาพร้อมคำสั่ง CLI ที่มี IP ของ R1 และ Subnet ของอุปกรณ์รอบข้างครบถ้วนเป๊ะๆ เพราะมัน **รู้บริบท (Context-aware)** มาตั้งแต่ต้นแล้วนั่นเองครับ!

---

**💡 อธิบายและขยายความ (Explanation):**

สิ่งที่โค้ดชุดนี้ทำคือเทคนิคที่เรียกว่า **RAG (Retrieval-Augmented Generation)** ครับ ปัญหาของ AI ทั่วไป (เช่น ChatGPT/Gemini หน้าเว็บ) คือมันฉลาดแต่ "มันไม่รู้จักบริษัทของเรา" ดังนั้นแทนที่เราจะให้ User ต้องมานั่งพิมพ์บอก AI ทุกครั้งว่า "R1 คือ Cisco รุ่น ISR4431 IP 192.168.1.1 บลาๆๆ ช่วย Config ให้หน่อย" โค้ดชุดนี้จะทำหน้าที่ไป **"แอบดึงข้อมูลจาก Database มายัดใส่ Prompt ให้เอง"** User จึงพิมพ์แค่สั้นๆ แต่ได้คำตอบที่เจาะจงกับระบบของเรา 100%

---

**🔗 ความสอดคล้องกับโปรเจกต์ MyNetMate ของเรา:**

โค้ดชุดนี้คือ **"ภาพสะท้อน Architecture ของ MyNetMate"** ในฝั่ง Backend (FastAPI) เลยครับ!

1. **การดึง Context จาก Database:** ในหนังสือเขาดึงข้อมูลจากไฟล์หลอกๆ (`devices.json`) แต่ของ MyNetMate เราทำล้ำกว่านั้นคือ เราจะดึงข้อมูลจริงจาก **PostgreSQL (Source of Truth)** ของเรา!
2. **การทำงานของ FastAPI:** เมื่อ User ถามเข้ามาในเว็บ MyNetMate ตัว Backend (FastAPI) ของเราจะทำตัวเป็น `NetworkCopilot` แบบในหนังสือเลยครับ คือไปสืบค้นข้อมูล Topology, IP, ยี่ห้อ (Cisco/MikroTik/Huawei) จาก Database แล้วนำมาเรียบเรียงเป็น Prompt ก่อนจะยิงส่งไปให้ **Gemini API**
3. **เจตนา (Intent):** การดักจับ Intent จะช่วยให้เราแยกว่า User แค่อยากถามเฉยๆ หรืออยากให้ MyNetMate ไปดึง Config ล่าสุดมาให้ (ถ้าอยากได้ Config เราก็เอา Intent นี้ไปสั่ง Netmiko ให้ทำงานต่อได้)

**สรุป:** สิ่งที่คุณออกแบบไว้ใน MyNetMate ตรงกับหลักการทำ AI Engine ในหนังสือเล่มนี้ทุกประการครับ (แถมเราใช้ Database จริงจังกว่าด้วย) เอาเนื้อหาตรงนี้ไปอธิบายเป็นทฤษฎีอ้างอิงกับอาจารย์ได้แบบหล่อๆ เลยครับ!
