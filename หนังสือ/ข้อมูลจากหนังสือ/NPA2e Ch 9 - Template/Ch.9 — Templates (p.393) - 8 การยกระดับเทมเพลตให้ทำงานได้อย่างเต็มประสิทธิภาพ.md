**"การยกระดับเทมเพลตให้ทำงานได้อย่างเต็มประสิทธิภาพขึ้นด้วยการฝังตรรกะแบบภาษา Python (Python-esque logic) ได้แก่ การใช้เงื่อนไข (Conditionals) และลูปวนซ้ำ (Loops) เข้าไปในไฟล์เทมเพลต Jinja"** เพื่อช่วยในการตัดสินใจเลือกคำสั่งที่จะเรนเดอร์ หรือช่วยย่อข้อมูลที่ซ้ำซ้อนให้เหลือเพียงกลุ่มก้อนเดียวแล้วนำมาคลี่ออกในตอนเรนเดอร์ ซึ่งช่วยเพิ่มขีดความสามารถในการขยายระบบเทมเพลตเพื่อรองรับการทำ Network Configuration Automation ได้อย่างเหมาะสม

หนังสือระบุเตือนว่า แม้เครื่องมือเหล่านี้จะมีพลังมาก แต่ก็เป็นเรื่องที่ต้องระวัง ไม่ควรใส่ตรรกะขั้นสูงที่ซับซ้อนเกินไปลงในเทมเพลต เพราะ Jinja ไม่ได้ถูกสร้างมาให้เป็นภาษาโปรแกรมมิ่งแบบเต็มตัว จึงควรดุลยภาพในการใช้งานให้ดี

## 2. รายละเอียดประเด็นหลักและตัวอย่างในหนังสือ

เนื้อหาถูกแบ่งออกเป็น 4 ส่วนตามการประยุกต์ใช้ตรรกะในรูปแบบต่างๆ ดังนี้ครับ:

### ส่วนที่ 1: การใช้ตรรกะเงื่อนไข (Conditional) สร้างคอนฟิก Switchport

ในงานเน็ตเวิร์ก พอร์ตของสวิตช์มักจะมีรูปแบบที่ต่างกัน เช่น บางพอร์ตเป็น VLAN Trunk และบางพอร์ตเป็น Access mode (เช่น พอร์ต Uplink ในสวิตช์ระดับ Access layer ที่ต้องอนุญาตให้ทุก VLAN ผ่านได้) หนังสือจึงนำคุณสมบัติบูลีน (Boolean) ที่ชื่อ `uplink` (ค่า True คือเป็นพอร์ต Uplink, ค่า False คือเป็นพอร์ต Access ทั่วไป) มาเขียนตรวจสอบเงื่อนไขในเทมเพลตด้วย Tag พิเศษของ Jinja คือ `{% ... %}` ดังนี้:

> **ตัวอย่างคำสั่งเงื่อนไขในเทมเพลต:**
> 
> Plaintext
> 
> ```
> interface {{ interface.name }}
> description {{ interface.description }}
> {% if interface.uplink %}
> switchport mode trunk
> {% else %}
> switchport access vlan {{ interface.vlan }}
> switchport mode access
> {% endif %}
> ```
> 
> - **การทำงาน:** ถ้าค่า `uplink` เป็น True อินเทอร์เฟซนั้นจะถูกคอนฟิกเป็น VLAN Trunk แต่ถ้าไม่ใช่ (เป็น False) จะถูกตั้งค่าเป็น Access mode พร้อมระบุหมายเลข VLAN ตามที่กำหนด
>     

_(หมายเหตุเรื่องช่องว่าง/Whitespace: หนังสือระบุว่า กระบวนการลบไวยากรณ์เทมเพลตออกของ Jinja อาจทำให้เกิดช่องว่างหรือการขึ้นบรรทัดใหม่ส่วนเกินในข้อความผลลัพธ์ ซึ่งสามารถจัดการได้โดยการใส่เครื่องหมายยติภังค์หรือขีดลบ เช่น `{% for item in seq -%}` เพื่อตัดช่องว่างออก แต่ในตัวอย่างของหนังสือได้ละเว้นส่วนนี้ไว้เพื่อให้โค้ดดูเรียบง่ายที่สุด)_

### ส่วนที่ 2: การใช้ลูปวนซ้ำ (Loop) สร้างคอนฟิก Switchport จำนวนมาก

เมื่อต้องการสร้างคอนฟิกสำหรับพอร์ตจำนวนมากในคราวเดียว หนังสือได้นำเสนอการใช้ `for loop` ซึ่งมีไวยากรณ์คล้ายกับภาษา Python โดยใช้ร่วมกับ Tag `{% ... %}` และฟังก์ชัน `range()`:

> **ตัวอย่างการใช้ลูปวนซ้ำ:**
> 
> Plaintext
> 
> ```
> {% for n in range(10) %}
> interface GigabitEthernet0/{{ n+1 }}
> description {{ interface.description }}
> switchport access vlan {{ interface.vlan }}
> switchport mode access
> {% endfor %}
> ```
> 
> - **การทำงาน:** เทมเพลตนี้จะเรียกใช้ฟังก์ชัน `range(10)` เพื่อสร้างตัวเลขมาวนลูป โดยในแต่ละรอบจะพิมพ์ผลลัพธ์เป็น `n+1` เนื่องจากฟังก์ชัน `range()` จะเริ่มต้นนับจาก 0 แต่ตามปกติแล้วพอร์ตของสวิตช์จะเริ่มต้นจากเลข 1 ผลลัพธ์ที่ได้คือจะได้คอนฟิกที่หน้าตาเหมือนกันทั้งหมดสำหรับสวิตช์พอร์ต 10 พอร์ต
>     

### ส่วนที่ 3: การผสมผสานลูปและเงื่อนไขเข้าด้วยกัน

หากต้องการให้บางพอร์ตในกลุ่มลูปนั้นมีคอนฟิกที่แตกต่างออกไป (เช่น กำหนดให้พอร์ตแรกสุดเป็น Trunk ส่วนพอร์ตที่เหลือเป็น Access) สามารถนำเงื่อนไขและลูปมารวมกันได้:

> **ตัวอย่างการผสมลูปและเงื่อนไข:**
> 
> Plaintext
> 
> ```
> {% for n in range(10) %}
> interface GigabitEthernet0/{{ n+1 }}
> description {{ interface.description }}
> {% if n+1 == 1 %}
> switchport mode trunk
> {% else %}
> switchport access vlan {{ interface.vlan }}
> switchport mode access
> {% endif %}
> {% endfor %}
> ```
> 
> - **การทำงาน:** ตัวแปร `n+1` ในรอบแรกสุดจะมีค่าเท่ากับ 1 ทำให้พอร์ต `GigabitEthernet0/1` ถูกตั้งค่าเป็น VLAN Trunk ส่วนรอบที่เหลือ (พอร์ต 2 ถึง 10) จะตกไป อยู่ในเงื่อนไข `{% else %}` กลายเป็น Access mode โดยหนังสือได้แสดงตัวอย่างผลลัพธ์ที่เรนเดอร์ออกมาสำเร็จแล้วดังนี้:
>     
> 
> Plaintext
> 
> ```
> interface GigabitEthernet0/1
> description TRUNK INTERFACE
> switchport mode trunk
> interface GigabitEthernet0/2
> description ACCESS INTERFACE
> switchport mode access
> ...
> ```

### ส่วนที่ 4: การวนลูปบนโครงสร้างข้อมูลแบบ List และ Dictionary

ในสถานการณ์จริง เรามักจะต้องส่งข้อมูลที่เป็นชุดข้อความหรือชุดตัวแปรเข้ามาเรนเดอร์ หนังสือจึงแสดงวิธีการวนลูปผ่าน List และ Dictionary:

- **การวนลูปผ่าน List:** สมมติว่ามีตัวแปรภาษา Python ที่เป็น List รายชื่ออินเทอร์เฟซส่งเข้ามา:
    
    Python
    
    ```
    intlist = ["GigabitEthernet0/1", "GigabitEthernet0/2", "GigabitEthernet0/3"]
    print(template.render(interface_list=intlist))
    ```
    
    ในฝั่งเทมเพลต Jinja จะทำการอ้างอิงและวนลูปโดยตรงผ่านตัวแปร `iface` (และปรับเปลี่ยนเงื่อนไขเนื่องจากไม่มีตัวแปรนับรอบ `n` แล้ว) ดังนี้:
    
    Plaintext
    
    ```
    {% for iface in interface_list %}
    interface {{ iface }}
    {% if iface == "GigabitEthernet0/1" %}
    switchport mode trunk
    {% else %}
    switchport access vlan 10
    switchport mode access
    {% endif %}
    {% endfor %}
    ```
    
- **การวนลูปผ่าน Dictionary:** หากต้องการส่งข้อมูลที่มีคู่ของคีย์และมูลค่า (เช่น ชื่ออินเทอร์เฟซเป็นคีย์ และคำอธิบายพอร์ตเป็นมูลค่า):
    
    Python
    
    ```
    intdict = {
        "GigabitEthernet0/1": "Server port number one",
        "GigabitEthernet0/2": "Server port number two",
        "GigabitEthernet0/3": "Server port number three"
    }
    print(template.render(interface_dict=intdict))
    ```
    
    ในฝั่งเทมเพลต Jinja จะใช้การระบุรูปแบบเพื่อดึงข้อมูลออกมาใช้งาน คล้ายกับการเขียนใน Python โดยต้องไม่ลืมเติมคำสั่ง `.items()` เพื่อแตกค่าออกมา:
    
    Plaintext
    
    ```
    {% for name, desc in interface_dict.items() %}
    interface {{ name }}
    description {{ desc }}
    {% endfor %}
    ```
    
    - **การทำงาน:** ในแต่ละรอบของการวนลูป ตัวแปร `name` จะเก็บค่าที่เป็น Key (ชื่อพอร์ต) และ `desc` จะเก็บค่าที่เป็น Value (คำอธิบายพอร์ต) ซึ่งจะได้ผลลัพธ์ที่เรนเดอร์ออกมาเรียงตามลำดับอย่างถูกต้อง
        

_**การผสมผสานการใช้ List และ Dictionary ร่วมกันในการเขียนเทมเพลต เพื่อสร้างระบบการคอนฟิกอินเทอร์เฟซที่มีประสิทธิภาพสูง"** ควบคู่ไปกับ **"แนวปฏิบัติที่ดีในการแยกข้อมูล (Data) ออกจากโค้ดแอปพลิเคชัน"** โดยย้ายข้อมูลไปไว้ในไฟล์ภายนอกรูปแบบ YAML เพื่อช่วยให้ระบบจัดการเทมเพลตสามารถบำรุงรักษาได้ง่ายขึ้น (More maintainable) และเปิดโอกาสให้ผู้ที่ไม่มีประสบการณ์เขียนภาษา Python สามารถแก้ไขคอนฟิกเครือข่ายได้ง่าย

### ส่วนที่ 5:  การวนลูปบนโครงสร้างข้อมูล List ของ Dictionary (Example 9-6)

หนังสือระบุว่า ในหัวข้อนี้คุณจะได้รวมเทคนิคเรื่องลูปและเงื่อนไขทั้งหมดที่เรียนมา โดยกำหนดให้แอปพลิเคชันฝั่ง Python จัดเก็บข้อมูลในลักษณะดังนี้:

- อินเทอร์เฟซแต่ละตัวจะมี Dictionary เป็นของตัวเอง
    
- คีย์ (Keys) ภายในดิกชันนารีจะเป็นคุณลักษณะ (Attributes) ของอินเทอร์เฟซนั้นๆ เช่น `name`, `desc` หรือ `uplink`
    
- ดิกชันนารีของแต่ละอินเทอร์เฟซจะถูกจัดเก็บอยู่ภายใน List อีกทีหนึ่ง ซึ่งเป็นสิ่งที่เทมเพลตจะนำไปวนลูปเพื่อผลิตคอนฟิกออกมา
    

> **ตัวอย่างโครงสร้างข้อมูลใน Python และการส่งค่าให้เทมเพลต:**
> 
> Python
> 
> ```
> interfaces = [
>     {
>         "name": "GigabitEthernet0/1",
>         "desc": "uplink port",
>         "uplink": True
>     },
>     {
>         "name": "GigabitEthernet0/2",
>         "desc": "Server port number one",
>         "vlan": 10
>     },
>     {
>         "name": "GigabitEthernet0/3",
>         "desc": "Server port number two",
>         "vlan": 10
>     }
> ]
> print(template.render(interface_list=interfaces))
> ```

เมื่อโครงสร้างข้อมูลเป็นเช่นนี้ ในฝั่งเทมเพลต Jinja (Example 9-6) จะทำการวนลูปผ่านไอเทมใน List และสามารถอ้างอิงถึง Key ต่างๆ ที่อยู่ในดิกชันนารีจำเพาะของแต่ละรอบได้ทันที ดังนี้:

> **ตัวอย่างเทมเพลต Jinja (Example 9-6):**
> 
> Plaintext
> 
> ```
> {% for interface in interface_list %}
> interface {{ interface.name }}
> description {{ interface.desc }}
> {% if interface.uplink %}
> switchport mode trunk
> {% else %}
> switchport access vlan {{ interface.vlan }}
> switchport mode access
> {% endif %}
> {% endfor %}
> ```

_(คำแนะนำเพิ่มเติมเกี่ยวกับไวยากรณ์ Jinja: หนังสือระบุว่า การเข้าถึงข้อมูลในดิกชันนารีของ Jinja สามารถเขียนได้ 2 วิธีที่ให้ผลลัพธ์เหมือนกันทุกประการ คือ รูปแบบดั้งเดิมของ Python `dict['key']` หรือรูปแบบย่อ `dict.key` หากพยายามเข้าถึงคีย์ที่ไม่มีอยู่จริงจะเกิดข้อผิดพลาด Key Error ขึ้น อย่างไรก็ตาม คุณสามารถใช้เมธอด `.get()` ใน Jinja ได้ หากคีย์นั้นเป็นทางเลือกเสริม (Optional) หรือเมื่อต้องการให้คืนค่าอื่นกลับมาในกรณีที่คีย์ไม่มีอยู่จริง เช่น `dict.get(key, 'UNKNOWN')`)_

### ประเด็นที่ 2: การแยกข้อมูลไปไว้ในไฟล์ภายนอกรูปแบบ YAML (Example 9-7)

หนังสือระบุว่า **การฝังข้อมูล (Embed data) ลงไปในแอปพลิเคชัน Python โดยตรงอย่างตัวอย่างก่อนหน้านี้นั้น ถือเป็นรูปแบบที่ไม่ดี (Bad form)** ทางออกที่ดีกว่าคือการนำข้อมูลเหล่านั้นไปใส่ไว้ในไฟล์ **YAML** แยกต่างหาก แล้วทำการปรับปรุงโค้ดโปรแกรมให้ทำงานด้วยการนำเข้า (Import) ข้อมูลนี้มาก่อนที่จะนำไปเรนเดอร์เทมเพลต

การปฏิบัติตามแนวทางนี้มีข้อดีคือ ช่วยให้คนที่ไม่เคยมีประสบการณ์ด้านภาษา Python เลย ก็สามารถแก้ไขหรือปรับแต่งการตั้งค่าเครือข่ายได้ด้วยตัวเองอย่างง่ายดาย เพียงแค่เข้าไปเปลี่ยนแปลงค่าในไฟล์ YAML ที่เรียบง่ายนี้เท่านั้น

> **ตัวอย่างไฟล์ YAML สำหรับเก็บข้อมูล (Example 9-7 ชื่อไฟล์ data.yml):**
> 
> YAML
> 
> ```
> ---
> - name: GigabitEthernet0/1
>   desc: uplink port
>   uplink: true
> - name: GigabitEthernet0/2
>   desc: Server port number one
>   vlan: 10
> - name: GigabitEthernet0/3
>   desc: Server port number two
>   vlan: 10
> ```

เมื่อย้ายข้อมูลไปที่ไฟล์ YAML แล้ว โค้ดโปรแกรมภาษา Python ฉบับสมบูรณ์จะถูกปรับเปลี่ยนให้อ่านไฟล์และส่งต่อข้อมูลด้วยไลบรารี `yaml` (ซึ่งเคยศึกษาในบทที่ 8) ดังนี้:

> **ตัวอย่างโค้ดแอปพลิเคชัน Python ฉบับสมบูรณ์:**
> 
> Python
> 
> ```
> from jinja2 import Environment, FileSystemLoader
> import yaml
> 
> ENV = Environment(loader=FileSystemLoader('.'))
> template = ENV.get_template("template.jinja")
> 
> with open("data.yml") as f:
>     interfaces = yaml.safe_load(f)
> 
> print(template.render(interface_list=interfaces))
> ```

**สรุปผลลัพธ์จากหนังสือ:** โค้ดนี้สามารถใช้ร่วมกับเทมเพลตเดิมในตัวอย่าง Example 9-6 ได้ทันทีและให้ผลลัพธ์ที่เหมือนกันทุกประการ แต่มีความแตกต่างคือข้อมูลมาจากไฟล์ YAML ภายนอก ทำให้บำรุงรักษาได้ง่ายขึ้น ตัวไฟล์ Python ในตอนนี้จะทำหน้าที่เหลือเพียงแค่ตรรกะในการดึงข้อมูลและการสั่งเรนเดอร์เทมเพลตเท่านั้น ส่งผลให้ระบบเรนเดอร์เทมเพลตนี้มีความสามารถในการบำรุงรักษาและจัดการที่ดียิ่งขึ้น
