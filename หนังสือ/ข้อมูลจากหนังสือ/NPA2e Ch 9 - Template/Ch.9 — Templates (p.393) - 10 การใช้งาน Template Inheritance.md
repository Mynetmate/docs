
หัวข้อนี้พูดถึง **"การสืบทอดเทมเพลต (Template Inheritance)"** ซึ่งเป็นเครื่องมือในการจัดระเบียบเพื่อเชื่อมโยงเทมเพลตต่างๆ เข้าด้วยกันอย่างมีความหมายเพื่อสร้างเป็นคอนฟิกฉบับสมบูรณ์ หนังสือระบุว่า เมื่อเราสร้างเทมเพลตสำหรับการตั้งค่าเครือข่ายที่มีขนาดใหญ่และมีความสามารถมากขึ้น เราอาจต้องการแยกเทมเพลตออกเป็นชิ้นส่วนขนาดเล็กที่มีความเฉพาะทางมากขึ้นเพื่อเพิ่มความยืดหยุ่น เช่น การแยกเทมเพลตสำหรับการตั้งค่า VLAN, เทมเพลตสำหรับอินเทอร์เฟซ และเทมเพลตสำหรับโปรโตคอลการจัดเส้นทาง (Routing protocol)

Jinja เปิดโอกาสให้เราทำระบบสืบทอดไฟล์เทมเพลตได้ ซึ่งเป็นแนวทางที่สะดวกในการเข้ามาแก้ปัญหานี้ โดยในหัวข้อนี้ได้นำเสนอเครื่องมือ 2 รูปแบบหลัก คือ คำสั่ง `include` และคำสั่ง `block` ร่วมกับ `extends`

## 2. ตัวอย่างในหนังสือและการอธิบายอย่างละเอียด

หนังสือได้แสดงตัวอย่างและวิธีการใช้งานเครื่องมือการสืบทอดเทมเพลตไว้ทั้งหมด 3 ตัวอย่าง ดังนี้ครับ:

### เครื่องมือที่ 1: การใช้คำสั่ง `include`

การใช้คำสั่ง `include` ช่วยให้ผู้เขียนเทมเพลตสามารถประกอบคอนฟิกของสวิตช์ขึ้นมาจากชิ้นส่วนที่เป็นมอดูลาร์ต่างๆ ได้ ซึ่งเป็นวิธีที่ยอดเยี่ยมในการจัดระเบียบไฟล์เทมเพลตหลายๆ ไฟล์ให้เป็นระบบ

> **Example 9-11. Using include for Jinja template inheritance**
> 
> Plaintext
> 
> ```
> {% include 'vlans.jinja' %}
> {% for name, desc in interface_dict.items() %}
> interface {{ name }}
> description {{ desc }}
> {% endfor %}
> ```

- **คำอธิบายจากหนังสือ:** รูปแบบนี้จะทำการเรนเดอร์ไฟล์ที่ชื่อ `vlans.jinja` (ซึ่งเป็นไฟล์ที่เก็บเฉพาะคอนฟิกของ VLAN เอาไว้) แล้วนำข้อความผลลัพธ์ที่ได้ไปแทรกเข้าไว้ในเอาต์พุตการเรนเดอร์ของเทมเพลตปัจจุบันที่ไปดึงมันมา วิธีนี้ช่วยให้เราสามารถผลิตคอนฟิก VLAN ออกมาจากอีกไฟล์หนึ่งในขณะที่กำลังเขียนเทมเพลตตั้งค่าอินเทอร์เฟซได้
    

### เครื่องมือที่ 2: การใช้คำสั่ง `block` และ `extends`

เป็นวิธีการสืบทอดเทมเพลตที่ทรงพลังแต่มีความซับซ้อนมากกว่าวิธีแรก เนื่องจากมันจำลองรูปแบบมาจากระบบการสืบทอดอ็อบเจกต์ (Object inheritance) ในภาษาโปรแกรมมิ่งที่เป็นทางการอย่าง Python การใช้บล็อกช่วยให้เราสามารถกำหนดพื้นที่บางส่วนในเทมเพลตที่ยอมให้เทมเพลตลูก (Child template) เข้ามาเขียนทับหรือแทนที่ (Override) ได้ แต่ถ้าหากไม่มีเทมเพลตลูกมาสั่งแทนที่ ผลลัพธ์ในส่วนนั้นก็ยังคงแสดงข้อความเริ่มต้น (Default text) ตามที่กำหนดไว้ในเทมเพลตแม่ หนังสือได้แสดงตัวอย่างไฟล์แม่และไฟล์ลูกที่ทำงานร่วมกันไว้ดังนี้:

> **Example 9-12. Jinja block definition**
> 
> Plaintext
> 
> ```
> {% for interface in interface_list %}
> interface {{ interface.name }}
> description {{ interface.desc }}
> {% endfor %}
> !
> {% block http %}
> no ip http server
> no ip http secure-server
> {% endblock %}
> ```

- **คำอธิบายจากหนังสือสำหรับ Example 9-12:** สมมติให้เรียกเทมเพลตแม่นี้ว่า `no-http.jinja` ซึ่งเป็นตัวระบุว่า โดยปกติแล้วคุณต้องการที่จะปิดการใช้งานตัวฝังระบบ HTTP เซิร์ฟเวอร์ในสวิตช์ อย่างไรก็ตาม การประกาศข้อความล้อมรอบด้วยคำสั่ง `{% block http %}` และ `{% endblock %}` เอาไว้ จะเปิดโอกาสให้ระบบมีความยืดหยุ่นที่มากขึ้น
    

> **Example 9-13. Jinja block reference**
> 
> Plaintext
> 
> ```
> {% extends "no-http.jinja" %}
> {% block http %}
> ip http server
> ip http secure-server
> {% endblock %}
> ```

- **คำอธิบายจากหนังสือสำหรับ Example 9-13:** นี่คือการสร้างเทมเพลตลูกขึ้นมา โดยตั้งชื่อไฟล์ว่า `yes-http.jinja` ซึ่งถูกออกแบบมาเพื่อทำหน้าที่แทนที่บล็อกดังกล่าว และเปลี่ยนไปส่งเอาต์พุตที่เป็นคำสั่งเปิดใช้งาน HTTP เซิร์ฟเวอร์แทน
    
- บรรทัดแรกสุดในตัวอย่างนี้ระบุคำสั่ง `{% extends "no-http.jinja" %}` เพื่อขยายขอบเขตมาจากเทมเพลตแม่ ส่งผลให้การตั้งค่าคอนฟิกของอินเทอร์เฟซทั้งหมด (ที่ถูกเขียนไว้ในไฟล์แม่) ยังคงปรากฏอยู่ในผลลัพธ์การเรนเดอร์สุดท้ายอย่างครบถ้วน
    
- แต่เนื่องจากเราสั่งเรนเดอร์ผ่านตัวเทมเพลตลูก บล็อก `http` ของเทมเพลตลูกจึงเข้าไปเขียนแทนที่ (Override) บล็อก `http` ของเทมเพลตแม่ทันที ทำให้เราสามารถเปิดใช้งาน HTTP เซิร์ฟเวอร์ได้ง่ายๆ เพียงแค่เลือกสั่งเรนเดอร์ที่ไฟล์เทมเพลตลูกนี้
    
- หนังสือระบุทิ้งท้ายว่า การใช้บล็อกในลักษณะนี้มีประโยชน์อย่างมากสำหรับส่วนของการตั้งค่าคอนฟิกที่อาจจำเป็นต้องปรับเปลี่ยน แต่ไม่เหมาะหรือไม่สามารถรองรับได้ด้วยระบบการแทนที่ตัวแปรแบบดั้งเดิม (Traditional variable substitution)
    

> **ข้อมูลเพิ่มเติมจากหนังสือ:** เอกสารประกอบ (Documentation) ของ Jinja ในหัวข้อการสืบทอดเทมเพลตนั้น มีการลงรายละเอียดไว้ลึกและมากกว่านี้อีกมาก ซึ่งถือเป็นแหล่งข้อมูลที่ยอดเยี่ยมที่ควรทำบุ๊กมาร์กเก็บไว้ศึกษาเพิ่มเติมครับ
