
เนื้อหาในหัวข้อ **"Summary" (บทสรุป)** ของบทนี้ สามารถสรุปและอธิบายรายละเอียดโดยอิงตามข้อเท็จจริงที่ปรากฏในหนังสือได้ดังนี้ครับ

## 1. หัวข้อนี้พูดถึงอะไร?

หัวข้อนี้คือบทสรุปส่งท้ายของการใช้งานเทมเพลตในระบบอัตโนมัติสำหรับเครือข่าย (Network Automation) โดยสรุปประเด็นสำคัญได้ดังนี้:

- **การใช้งานเทมเพลตผ่านเครื่องมือ Automation โดยตรง:** หนังสือระบุว่าผู้ใช้งานไม่จำเป็นต้องทำงานร่วมกับภาษาโปรแกรมมิ่งอย่าง Go หรือ Python โดยตรงเพื่อที่จะใช้เทมเพลตเสมอไป เนื่องจากเครื่องมืออย่าง Ansible และ Nornir (ซึ่งจะกล่าวถึงในบทที่ 12) มีการรองรับภาษาเทมเพลตอย่าง Jinja2 มาในตัวอยู่แล้ว ทำให้สามารถนำข้อมูลที่มีอยู่ภายในแพลตฟอร์มเหล่านั้นมาเติมลงในเทมเพลตได้ทันที
    
- **ข้อแนะนำ 4 ประการในการใช้งานเทมเพลตสำหรับเครือข่าย:**
    
    1. **รักษาความเรียบง่ายของเทมเพลต:** การใช้ลูป (Loops) และเงื่อนไข (Conditionals) เพื่อเพิ่มความสามารถให้เทมเพลตนั้นสามารถทำได้ แต่ไม่ควรทำจนเกินขอบเขต เนื่องจาก Jinja ไม่ได้มีความทนทานหรือแข็งแกร่งเท่ากับภาษาโปรแกรมมิ่งทั่วไปที่มีฟีเจอร์ครบถ้วนอย่าง Python จึงควรแยกส่วนการทำงานที่ขั้นสูงและซับซ้อนออกไปจากเทมเพลต
        
    2. **ใช้ประโยชน์จากการสืบทอดเทมเพลต (Template Inheritance):** นำมาใช้เพื่อนำส่วนของการตั้งค่าคอนฟิกที่ไม่จำเป็นต้องทำซ้ำกลับมาใช้ใหม่
        
    3. **แยกไวยากรณ์และข้อมูลออกจากกัน:** ต้องจัดการโครงสร้างคำสั่งและข้อมูลแยกออกจากกันอย่างชัดเจน
        
    4. **ใช้งานระบบควบคุมเวอร์ชัน (Version Control):** เนื่องจากเทมเพลตเป็นเพียงไฟล์ข้อความ (Text files) ผู้ใช้จึงสามารถและควรใช้ระบบควบคุมเวอร์ชัน เช่น Git ในการติดตามการเปลี่ยนแปลงและทำงานร่วมกับผู้อื่น (ซึ่งจะกล่าวถึงในบทที่ 11)
        

## 2. ตัวอย่างในหนังสือและการอธิบาย

ในเนื้อหาส่วนบทสรุปนี้ไม่มีตัวอย่างโค้ดสไนเป็ตแยกเฉพาะเหมือนหัวข้อก่อนหน้า แต่มีการยกตัวอย่างเชิงแนวคิดประกอบไว้ในข้อแนะนำ ซึ่งมีรายละเอียดดังนี้ครับ:

- **ตัวอย่างที่หนังสือยกขึ้นมา:** การเก็บหมายเลข VLAN (VLAN IDs) เอาไว้ในไฟล์ข้อมูลของตัวเองต่างหาก (เช่น ไฟล์รูปแบบ YAML) และแยกส่วนไวยากรณ์ CLI (CLI syntax) ที่ใช้ในการติดตั้งหรือสั่งงาน VLAN เหล่านั้นไว้ในไฟล์เทมเพลตที่ถูกสร้างขึ้นมาโดยเฉพาะ
    
- **คำอธิบายจากหนังสือ:** ตัวอย่างนี้แสดงถึงหลักการจัดการแยกกันระหว่างไวยากรณ์และข้อมูล (Syntax and data should be handled separately) โดยให้ไฟล์ข้อมูล (เช่น YAML) ทำหน้าที่เก็บเฉพาะค่าดิบหรือตัวแปรอย่างหมายเลข VLAN ส่วนไฟล์เทมเพลตจะทำหน้าที่คุมโครงสร้างของคำสั่ง CLI เฉพาะเจาะจงที่ใช้สั่งการอุปกรณ์เครือข่าย เพื่อไม่ให้เกิดความซ้ำซ้อนในระบบคอนฟิก
