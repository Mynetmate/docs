เนื้อหาในหัวข้อ **"Go Templates"** สามารถสรุปและอธิบายรายละเอียดโดยอิงตามข้อเท็จจริงที่ปรากฏในหนังสือได้ดังนี้ครับ

## 1. หัวข้อนี้พูดถึงอะไร?

หัวข้อนี้พูดถึง **"การใช้งานระบบเทมเพลตในภาษาโปรแกรมมิ่ง Go (Go Templates)"** ผ่านแพ็กเกจมาตรฐานที่มีมาให้ในระบบชื่อ `text/template` ซึ่งมีประเด็นสำคัญดังนี้:

- **การบูรณาการกับภาษา Go:** แพ็กเกจนี้ใช้สร้างและเรนเดอร์เทมเพลตที่มีความเชื่อมโยงและบูรณาการเข้ากับภาษา Go อย่างหนาแน่น ทำให้เป็นตัวเลือกที่มั่นคงและเหมาะสมอย่างยิ่งหากผู้ใช้กำลังทำงานด้วยภาษา Go เป็นหลัก
    
- **ไวยากรณ์และความคล้ายคลึงกับ Jinja:** ภาษาเทมเพลตนี้มีความเฉพาะเจาะจงสำหรับ Go ทำให้มีคำสำคัญ (Keywords) และไวยากรณ์ในสไตล์แบบ Go แต่ก็ยังมีแนวคิดที่คล้ายคลึงกับภาษาเทมเพลตอื่นๆ เช่น Jinja โดยเฉพาะไวยากรณ์ของการแทนที่ข้อความจริง (Text replacement syntax) ที่ใช้เครื่องหมายปีกกาคู่ `{{ }}` เหมือนกัน
    
- **กรณีใช้งานหลักใน Network Automation:** เช่นเดียวกับ Jinja จุดประสงค์หลักของการใช้ Go templates ในระบบอัตโนมัติสำหรับเครือข่ายคือ การฉีดข้อมูลที่มีโครงสร้าง (Structured data) เข้าไปในรูปแบบเอาต์พุตที่ถูกกำหนดไว้ล่วงหน้า ช่วยให้ข้อความหลักคงความสม่ำเสมอ (Consistent) ในขณะที่นำข้อมูลจากพารามิเตอร์ของผู้ใช้หรือการเรียกผ่าน API มาทำหน้าที่ "เติมเต็ม" ส่วนที่ต้องการความยืดหยุ่น
    
- **ฟีเจอร์การควบคุมและท่อข้อมูล:** Go templates รองรับการทำงานขั้นพื้นฐานครบถ้วน ทั้งการวนลูปด้วย `range` การเช็กเงื่อนไขด้วย `if` การรองรับข้อมูลแบบ Map รวมถึงฟีเจอร์ที่เรียกว่า **Pipelines** (ทาง Go ใช้คำนี้แทนคำว่า Filters ใน Jinja) ซึ่งใช้เครื่องหมายท่อ `|` ในการส่งต่อชุดคำสั่ง ตลอดจนการสร้างฟังก์ชันสั่งทำพิเศษ (Custom functions) เข้าไปใช้งานร่วมกับเทมเพลต
    

## 2. ตัวอย่างทั้งหมดในหนังสือและการอธิบายอย่างละเอียด

หนังสือได้แสดงตัวอย่างการโค้ดดิ้งและการประยุกต์ใช้งานระบบเทมเพลตของ Go ไว้ทั้งหมดตามลำดับดังนี้ครับ:

### ตัวอย่างที่ 1: เทมเพลตขั้นพื้นฐาน (Example 9-17)

หนังสือเริ่มต้นด้วยการสร้างเทมเพลตอย่างง่ายจากการใช้ข้อความดิบ (String literal) ที่กำหนดไว้ภายในโปรแกรม Go และพิมพ์ผลลัพธ์ออกทางหน้าจอ Terminal

Go

```
// Example 9-17. Simple Go template
package main

import (
	"os"
	"text/template"
)

func main() {
	// We can create an inline template using the Parse() method of the
	// template.Template type
	// Note that simpleTemplate is just an arbitrary name chosen for this example.
	tmpl, err := template.New("simpleTemplate").Parse(`{{ "foobar" | print }}`)
	if err != nil {
		panic(err)
	}

	// We can render the template with Execute, passing in os.Stdout
	// as the first parameter, so we can see the results in our terminal
	err = tmpl.Execute(os.Stdout, nil)
	if err != nil {
		panic(err)
	}
}
```

- **คำอธิบายจากหนังสือ:** โค้ดนี้เป็นตัวอย่างฉบับเต็มที่ทำงานได้จริงผ่านคำสั่ง `go run` โดยใช้เมธอด `Parse()` ของประเภทข้อมูล `template.Template` เพื่อสร้างเทมเพลตแบบอินไลน์ (Inline template) ในตัวอย่างนี้ยังไม่มีการแทนที่ตัวแปรใดๆ ทั้งสิ้น แต่ Go templates อนุญาตให้เรากำหนดค่า String literal ไว้ข้างในเทมเพลตได้เลย (ทำให้ต้องใช้เครื่องหมายคำพูดซ้อนข้างใน) ผลลัพธ์จากตัวอย่างนี้จึงแสดงคำว่า `foobar` ออกมาตรงๆ โดยสั่งเรนเดอร์ผ่านเมธอด `Execute()` และส่งพารามิเตอร์แรกเป็น `os.Stdout` เพื่อให้ผลลัพธ์แสดงบน Terminal
    

### ตัวอย่างที่ 2: การเรนเดอร์เทมเพลตลงไฟล์ (Example 9-18)

หนังสือชี้ให้เห็นว่าผลลัพธ์การเรนเดอร์ไม่จำเป็นต้องส่งไปยังหน้าจอ (Stdout) เสมอไป

Go

```
// Example 9-18. Rendering a template to a file
tmpl, err := template.New("simpleTemplate").Parse(`{{ "foobar" | print }}`)
if err != nil {
	panic(err)
}

file, err := os.Create("./output.txt")
if err != nil {
	panic(err)
}

err = tmpl.Execute(file, nil)
if err != nil {
	panic(err)
}
```

- **คำอธิบายจากหนังสือ:** อะไรก็ตามที่ตอบสนองหรือสอดคล้องกับอินเทอร์เฟซ `io.Writer` สามารถนำมาใช้เป็นพารามิเตอร์แรกในฟังก์ชัน `Execute()` ได้ทั้งหมด ซึ่งรวมถึงอ็อบเจกต์ไฟล์ที่ถูกส่งกลับมาจากคำสั่ง `os.Create()` เพื่อสร้างไฟล์รับข้อมูลปลายทางด้วย
    

### ตัวอย่างที่ 3: การส่งข้อมูลผ่าน Struct และแนวคิดเรื่อง "Dot" (Example 9-19)

หนังสือแสดงตัวอย่างการนำข้อมูลจริงส่งเข้าไปในเทมเพลตผ่านโครงสร้างข้อมูลประเภท Struct

Go

```
// Example 9-19. Passing data into a template via a struct
type Switch struct {
	Hostname       string
	InterfaceCount uint
}

sw01 := Switch{"sw01", 48}

tmpl, err := template.New("switchTemplate").Parse("Device {{.Hostname}} has {{.InterfaceCount}} interfaces\n")
if err != nil {
	panic(err)
}

err = tmpl.Execute(os.Stdout, sw01)
if err != nil {
	panic(err)
}
```

- **คำอธิบายจากหนังสือ:**
    
    - ขั้นแรก โค้ดจะทำการนิยาม Struct ที่ชื่อ `Switch` เพื่อเป็นตัวแทนของสวิตช์เครือข่าย จากนั้นสร้างอินสแตนซ์ (Instantiate) โครงสร้างนี้เก็บไว้ในตัวแปรชื่อ `sw01`
        
    - ในฝั่งเทมเพลต เราสามารถอ้างอิงถึงฟิลด์ข้อมูลภายใน Struct ได้โดยการใช้ไวยากรณ์เครื่องหมายจุดนำหน้าตามด้วยชื่อฟิลด์ เช่น `{{.Hostname}}` และ `{{.InterfaceCount}}`
        
    - ตัวแปรโครงสร้างข้อมูลอินพุตจะถูกส่งผ่านเข้าไปเป็นพารามิเตอร์ตัวที่สองของฟังก์ชัน `Execute()`
        
    - **แนวคิดเรื่อง Dot (.):** ในเอกสารประกอบของแพ็กเกจ Go จะเรียกเครื่องหมายจุดนำหน้านี้ว่า **"dot"** ซึ่งมันคือตัวสะท้อนหรืออ้างอิงถึงประเภทข้อมูลใดๆ ก็ตามที่ถูกส่งเข้ามาในบริบท (Context) ของเทมเพลตนั้นๆ ซึ่งในกรณีนี้ dot คือข้อมูลโครงสร้าง Struct ทั่วไปที่มีฟิลด์ให้เรียกตามชื่อ แต่อาจไม่เป็นเช่นนี้เสมอไปในตัวอย่างถัดไป
        
    - ผลลัพธ์ที่พิมพ์ออกมาจากตัวอย่างนี้คือ: `Device sw01 has 48 interfaces`
        

### ตัวอย่างการวนลูปผ่าน Slice ข้อมูล (ไม่มีเลข Example กำหนด)

หนังสือแสดงการเปลี่ยนจากการส่ง Struct เดี่ยวๆ เป็นการส่งชุดข้อมูลแบบ Slice ของ Switch หลายๆ ตัวเข้ามา แล้วใช้คำสำคัญ `range` ในการวนลูป

Go

```
type Switch struct {
	Hostname       string
	InterfaceCount uint
}

// switches is a slice that represents all our Switch instances
switches := []Switch{
	{"sw01", 48},
	{"sw02", 24},
	{"sw03", 48},
}

tmplStr := `
{{range $i, $switch := .}}
Device {{$switch.Hostname}} has {{$switch.InterfaceCount}} interfaces
{{end}}
`
```

- **คำอธิบายจากหนังสือ:** ในกรณีนี้ **dot (.) จะทำหน้าที่เป็นตัวแทนของข้อมูล Slice ทั้งหมดที่คุณส่งเข้ามา** การสั่งวนลูปบน Slice ในเทมเพลตจะทำผ่านคำสั่ง `range $i, $switch := .` ซึ่งมีลักษณะการทำงานเหมือนกับการวนลูปบน Slice ในภาษา Go ปกติ โดย Slice จะอยู่ทางขวาของตัวดำเนินการประกาศตัวแปรอย่างย่อ `:=` และมีตัวแปร `$i` แทนค่าดัชนี (Index) กับตัวแปร `$switch` แทนสำเนาข้อมูลของไอเทมในรอบนั้นๆ ตามลำดับ _(หมายเหตุ: หนังสือแนะนำเพิ่มเติมว่า ในการทำงานจริง ควรเขียนเทมเพลตในลักษณะข้อความหลายบรรทัด / Multiline string แบบตัวแปร `tmplStr` หรือแยกออกไปเป็นไฟล์ต่างหากก่อนจะอ่านเข้ามาเรนเดอร์)_
    

### ตัวอย่างการใช้เงื่อนไข (Conditional Logic) (ไม่มีเลข Example กำหนด)

หนังสือแสดงให้เห็นว่า Go templates รองรับการทำงานของตรรกะเงื่อนไขเช่นกัน โดยเพิ่มฟิลด์บูลีน `Enabled` เข้ามาในโครงสร้างข้อมูล

Go

```
type Switch struct {
	Hostname       string
	InterfaceCount uint
	Enabled        bool
}

// switches is a slice that represents all our Switch instances
switches := []Switch{
	{"sw01", 48, true},
	{"sw02", 24, true},
	{"sw03", 48, false},
}

tmplStr := `
{{range $i, $switch := .}}
{{if $switch.Enabled}}
Device {{$switch.Hostname}} has {{$switch.InterfaceCount}} interfaces
{{end}}
{{end}}
`
```

- **คำอธิบายจากหนังสือ:** คุณสามารถเลือกสั่งให้พิมพ์บรรทัดข้อความออกมาเฉพาะพอร์ตหรืออุปกรณ์ที่ผ่านเงื่อนไขได้ โดยการตรวจสอบค่าบูลีนจากฟิลด์ข้อมูลผ่านคำสั่ง `{{if $switch.Enabled}}`
    

### ตัวอย่างการวนลูปข้อมูลรูปแบบ Map (ไม่มีเลข Example กำหนด)

หนังสือชี้ให้เห็นว่าคุณสามารถลดทอนความยุ่งยากของโครงสร้างข้อมูลจาก Struct ให้เหลือเพียงข้อมูลประเภท **Map** และนำมาวนลูปใช้งานได้เช่นกัน

Go

```
switches := map[string]int{
	"sw01": 48,
	"sw02": 24,
	"sw03": 48,
}

tmplStr := `
{{range $hostname, $ifCount := .}}
Device {{$hostname}} has {{$ifCount}} interfaces
{{end}}
`
```

- **คำอธิบายจากหนังสือ:** เนื่องจากการทำงานในรอบนี้เป็นการวนลูปบนข้อมูลประเภท Map ตัวแปรสองตัวที่ถูกสร้างขึ้นมาหลังคำสำคัญ `range` (คือ `$hostname` และ `$ifCount`) จะทำหน้าที่เป็นตัวแทนของคู่คีย์และมูลค่า (Key/Value pair) ของแต่ละรอบการวนลูปโดยอัตโนมัติ
    

### ตัวอย่างการใช้ Pipelines และคำสั่ง `len` (Example 9-20)

หนังสือนำเสนอการใช้ฟีเจอร์ **Pipelines** ซึ่งทำงานด้วยการส่งต่อชุดคำสั่งผ่านเครื่องหมาย `|` โดยปรับเปลี่ยนโครงสร้างให้ฟิลด์อินเทอร์เฟซเก็บค่าเป็น Slice ของข้อความรายชื่อพอร์ตแทนตัวเลขจำนวนเต็มตรงๆ

Go

```
// Example 9-20. Go template pipelines
// A fairly small switch, indeed
sw01 := Switch{"sw01", []string{
	"ge-0/0/1",
	"ge-0/0/2",
	"ge-0/0/3",
	"ge-0/0/4",
}}

tmplStr := "Device {{.Hostname}} has {{ .Interfaces | len }} interfaces\n"
```

- **คำอธิบายจากหนังสือ:** โค้ดนี้เรียกใช้คำสั่งพื้นฐานที่มีมาให้ในตัวอย่างคำสั่ง `len` ผ่านระบบท่อส่งข้อมูล (`|`) เพื่อทำหน้าที่นับและพิมพ์ขนาดความยาว (Length) ของข้อมูลที่ถูกส่งผ่านมาหาตัวมัน แทนที่จะพิมพ์ค่าของข้อมูลนั้นออกมาตรงๆ ผลลัพธ์ที่ได้คือ: `Device sw01 has 4 interfaces` นอกจากนี้หนังสือยังระบุคำสั่งอื่นๆ ที่มีให้ใช้งานในระบบ เช่น `slice` (สำหรับตัดแบ่งอาร์กิวเมนต์ย่อย), คำสั่ง `and` กับ `or` (สำหรับเปรียบเทียบค่าความว่างเปล่าของสองอาร์กิวเมนต์) และคำสั่ง `call` (สำหรับใช้เรียกฟังก์ชัน)
    

### ตัวอย่างการสร้างและเรียกใช้ฟังก์ชันสั่งทำพิเศษ (Custom Functions)

หนังสืออธิบายว่าคุณสามารถสร้างฟังก์ชันขึ้นมาเองและเปิดสิทธิ์ให้ระบบเทมเพลตเรียกใช้งานมันได้ในตอนสร้างเทมเพลต โดยเริ่มต้นจากการนิยามฟังก์ชันภาษา Go ทั่วไปขึ้นมาก่อนดังนี้:

**1. การนิยามโครงสร้างและฟังก์ชัน `IfParse()` (ไม่มีเลข Example กำหนด)**

Go

```
type Interface struct {
	Speed int
	FPC   int
	PIC   int
	Port  int
}

func IfParse(ifaceStr string) Interface {
	iface := Interface{}
	ifSplit := strings.Split(ifaceStr, "-")
	speeds := map[string]int{
		"ge": 1,
		"xe": 10,
		"et": 40,
	}
	iface.Speed = speeds[ifSplit[0]]
	locSplit := strings.Split(ifSplit[1], "/")
	fpc, _ := strconv.Atoi(locSplit[0])
	iface.FPC = fpc
	pic, _ := strconv.Atoi(locSplit[1])
	iface.PIC = pic
	port, _ := strconv.Atoi(locSplit[2])
	iface.Port = port
	return iface
}
```

- **คำอธิบายจากหนังสือ:** ฟังก์ชัน `IfParse()` นี้ถูกสร้างขึ้นมาเพื่อทำหน้าที่แยกแยะรายละเอียดความเร็ว (Speed) และตำแหน่ง (Location) ออกมาจากสตริงชื่ออินเทอร์เฟซเครือข่ายที่ส่งเข้ามาเป็นอาร์กิวเมนต์
    

**2. การลงทะเบียนและเรียกใช้งานฟังก์ชันสั่งทำพิเศษในเทมเพลต (Example 9-21)** ในการนำฟังก์ชันที่เขียนไว้ข้างต้นไปใช้งานในเทมเพลต คุณจำเป็นต้องสร้างแผนผังจับคู่ระหว่างตัวฟังก์ชันกับชื่อที่คุณต้องการใช้อ้างอิงในเทมเพลตผ่านฟังก์ชัน `template.FuncMap()` จากนั้นต้องไม่ลืมส่งต่อฟังก์ชันนี้เข้าไปผ่านเมธอด `Funcs()` ของอ็อบเจกต์เทมเพลตด้วย

Go

```
// Example 9-21. Using custom functions in Go templates
fmap := template.FuncMap{"ifparse": IfParse}

sw01 := Switch{"sw01", []string{
	"ge-0/0/1",
	"ge-0/0/2",
	"ge-0/0/3",
	"ge-0/0/4",
}}

tmplStr := `
{{range $i, $interface := .Interfaces}}
	{{with $loc := $interface | ifparse}}
		Interface {{$interface}} port {{$loc.Port}}
	{{end}}
{{end}}
`

tmpl, err := template.New("switchTemplate").Funcs(fmap).Parse(tmplStr)
if err != nil {
	panic(err)
}
```

- **คำอธิบายจากหนังสือ:**
    
    - แผนผังการจับคู่ถูกสร้างขึ้นผ่านคำสั่ง `fmap := template.FuncMap{"ifparse": IfParse}` เพื่อให้เราเรียกชื่อฟังก์ชันในเทมเพลตสั้นๆ ว่า `ifparse`
        
    - ภายในโค้ดเทมเพลต มีการสร้างตัวแปรใหม่ชื่อว่า `loc` ขึ้นมา โดยเกิดจากการส่งต่อข้อมูลตัวแปร `$interface` ผ่านระบบท่อข้อมูล (Pipeline) เข้าไปประมวลผลในฟังก์ชันสั่งทำพิเศษอย่าง `ifparse`
        
    - และเนื่องจากฟังก์ชัน `ifparse` ส่งคืนข้อมูลกลับมาเป็นประเภท `Interface` (ตามที่นิยามไว้ในโครงสร้างข้างต้น) ส่งผลให้เราสามารถอ้างอิงและเจาะเข้าถึงฟิลด์ย่อยภายในโครงสร้างนั้นได้โดยตรงทันที เช่นการเขียนระบุตำแหน่งพอร์ตด้วยคำสั่ง `{{$loc.Port}}`
        
    - การส่งผ่านข้อมูล `FuncMap` เข้าสู่ระบบทำผ่านคำสั่ง `template.New("switchTemplate").Funcs(fmap).Parse(tmplStr)`
        
    - ผลลัพธ์สุดท้ายที่ได้จากการสั่งพิมพ์ออกมาคือ:
        
        Plaintext
        
        ```
        Interface ge-0/0/1 port 1
        Interface ge-0/0/2 port 2
        Interface ge-0/0/3 port 3
        Interface ge-0/0/4 port 4
        ```
        

> **สรุปคำแนะนำจากหนังสือ:** แม้ว่าจะมีสิ่งให้ศึกษาและค้นหาใน Go templates อีกมาก แต่ข้อมูลเหล่านี้คือพื้นฐานทั้งหมดที่ครอบคลุมไว้ หากคุณทำงานกับ Go และมีความคุ้นเคยกับแนวคิดพื้นฐานเรื่องเทมเพลตที่ได้อภิปรายไปแล้วในหัวข้อ Jinja การพัฒนาทักษะเพิ่มเติมในเรื่อง Go templates ถือเป็นสิ่งที่ดีและไม่เสียหายครับ
