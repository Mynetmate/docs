หัวข้อนี้พูดถึง **"กระบวนการและวิธีการนำเทมเพลต Jinja ไปเรนเดอร์ (สั่งงาน) ด้วยภาษา Python และไลบรารี Jinja2"** เพื่อนำข้อมูลจริงเข้าไปเติมในช่องตัวแปรของเทมเพลตจนได้ผลลัพธ์สุดท้ายออกมา โดยหนังสือได้อธิบายตั้งแต่ขั้นตอนการเตรียมระบบ การนำเข้าข้อมูลผ่านโครงสร้างแบบดิกชันนารี (Dictionary) ไปจนถึงการใช้คลาส (Class) ใน Python ซึ่งแสดงให้เห็นถึงความยืดหยุ่นของไลบรารีนี้

เนื้อหาหลักแบ่งออกเป็นประเด็นสำคัญพร้อมตัวอย่างและขั้นตอนตามลำดับที่หนังสือระบุไว้ดังนี้ครับ:

### ข้อจำกัดและการติดตั้งไลบรารี

- **ชื่อไลบรารี:** ตัวภาษาเทมเพลตจะเรียกว่า Jinja แต่ตัวไลบรารีใน Python สำหรับทำงานร่วมกับมันจะเรียกว่า **Jinja2**
    
- **การติดตั้ง:** ตัวเครื่องมือเรนเดอร์ Jinja2 ใน Python ไม่ได้เป็นส่วนหนึ่งของ Standard library (ไม่ได้ติดตั้งมาให้พร้อมระบบ) ดังนั้นจึงไม่ได้ถูกติดตั้งไว้ตั้งแต่แรก แต่ผู้ใช้สามารถติดตั้งได้ผ่านคำสั่ง `pip3 install jinja2` เหมือนกับแพ็กเกจ Python อื่นๆ บน PyPI (ตามที่เคยครอบคลุมในบทที่ 6)
    

### ขั้นตอนการสั่งเรนเดอร์ผ่าน Python Interpreter

หนังสือได้พาทำทีละขั้นตอนผ่าน Python Interpreter เพื่อให้ผู้ใช้อามารถทดลองทำตามบนเครื่องของตัวเองได้ โดยใช้เทมเพลตพอร์ตสวิตช์จากตัวอย่างก่อนหน้า (Example 9-4) ดังนี้:

#### ขั้นที่ 1: การเตรียมสภาพแวดล้อม (Environment) และโหลดไฟล์เทมเพลต

เริ่มจากการนำเข้าอ็อบเจกต์ที่จำเป็น ตั้งค่าโฟลเดอร์ที่เก็บไฟล์ และดึงไฟล์เทมเพลตเข้ามา:

Python

```
>>> from jinja2 import Environment, FileSystemLoader
>>> ENV = Environment(loader=FileSystemLoader('.'))
>>> template = ENV.get_template("template.jinja")
```

- บรรทัดแรกเป็นการตั้งค่าอ็อบเจกต์ `Environment` โดยระบุเครื่องหมายจุด `.` เพื่อบอกให้ตัวเรนเดอร์รู้ว่าไฟล์เทมเพลตอยู่ในไดเรกทอรีเดียวกันกับที่เปิดใช้งาน Python interpreter
    
- บรรทัดที่สองเป็นการดึงอ็อบเจกต์เทมเพลตมาจาก Environment นั้น โดยระบุชื่อไฟล์ตรงๆ ว่า `template.jinja`
    

#### ขั้นที่ 2: การเตรียมข้อมูล (Data)

หนังสือระบุว่าคุณจำเป็นต้องมีข้อมูล ซึ่งในที่นี้จะกำหนดผ่าน Dictionary โดยคีย์ (Keys) ของดิกชันนารีนี้จะต้องตรงกับชื่อฟิลด์ที่อ้างอิงไว้ในเทมเพลต:

Python

```
>>> interface_dict = {
... "name": "GigabitEthernet0/1",
... "description": "Server Port",
... "vlan": 10,
... "uplink": False
... }
```

_(หมายเหตุจากหนังสือ: ในความเป็นจริง คุณอาจไม่ต้องสร้างโครงสร้างข้อมูลด้วยตัวเองใน Python แบบนี้ เพราะนี่ทำขึ้นเพื่อวัตถุประสงค์ในการสาธิตเท่านั้น โดยปกติแล้วคุณจะต้องการดึงข้อมูลมาจาก API หรือไฟล์บนดิสก์ มากกว่าการประกาศค่าไว้เฉยๆ ในโปรแกรมหรือสคริปต์)_

#### ขั้นที่ 3: การสั่งเรนเดอร์และแสดงผลลัพธ์

ส่งข้อมูลเข้าเครื่องยนต์เรนเดอร์ผ่านฟังก์ชัน `render()` และใช้ `print()` เพื่อแสดงผลออกทางหน้าจอ:

Python

```
>>> print(template.render(interface=interface_dict))
interface GigabitEthernet0/1
description Server Port
switchport access vlan 10
switchport mode access
```

**ข้อสังเกตสำคัญจากหนังสือ:** ให้ใส่ใจกับชื่ออาร์กิวเมนต์ที่ส่งเข้าไปในฟังก์ชัน `render()` ตัวแปรคีย์เวิร์ดที่ชื่อว่า `interface` จะต้องตรงกับการอ้างอิงคำว่า `interface` ที่อยู่ภายในเทมเพลต Jinja นี่คือวิธีนำเอาดิกชันนารีเข้าไปในระบบเรนเดอร์ เมื่อระบบเห็นการอ้างอิงถึง `interface` หรือคีย์ของมัน มันจะนำดิกชันนารีที่ส่งผ่านตรงนี้ไปตอบรับการอ้างอิงนั้นทันที

### การเปลี่ยนไปใช้ Python Class ในการเติมข้อมูล (Example 9-5)

หนังสือระบุเพิ่มเติมว่า คุณไม่จำเป็นต้องใช้ดิกชันนารีเสมอไป เพราะเป็นเรื่องปกติเช่นกันที่จะขับเคลื่อนข้อมูลจากไลบรารีอื่นของ Python เข้าสู่เทมเพลต Jinja ซึ่งอาจมาในรูปแบบของ **Python class**

> **ตัวอย่างที่เขียนด้วยคลาส (Example 9-5):**
> 
> Python
> 
> ```
> from jinja2 import Environment, FileSystemLoader
> ENV = Environment(loader=FileSystemLoader('.'))
> template = ENV.get_template("template.jinja")
> 
> class NetworkInterface(object):
>     def __init__(self, name, description, vlan, uplink=False):
>         self.name = name
>         self.description = description
>         self.vlan = vlan
>         self.uplink = uplink
> 
> interface_obj = NetworkInterface("GigabitEthernet0/1", "Server Port", 10)
> print(template.render(interface=interface_obj))
> ```

**สรุปจากหนังสือ:** ผลลัพธ์ (Output) ที่ได้จากโปรแกรมที่ใช้คลาสนี้จะเหมือนกันกับผลลัพธ์ก่อนหน้านี้ทุกประการ ดังนั้น จึงไม่มีวิธีที่ "ถูกที่สุดเพียงวิธีเดียว" ในการนำข้อมูลไปใส่ในเทมเพลต Jinja แต่มันขึ้นอยู่กับว่าข้อมูลนั้นมาจากไหน ซึ่งโชคดีที่ไลบรารี Jinja2 ของ Python เปิดโอกาสให้มีความยืดหยุ่นในจุดนี้ครับ
