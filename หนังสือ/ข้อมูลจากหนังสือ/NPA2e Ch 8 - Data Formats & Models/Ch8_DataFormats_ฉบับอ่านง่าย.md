# 📖 สรุปเนื้อหาบทที่ 8 (ครึ่งแรก): Data Formats Concepts (ฉบับอ่านง่าย)

**เป้าหมายของบทนี้:** อธิบายถึง "ภาษากลาง" ที่สคริปต์บนแล็ปท็อปของเราใช้เพื่อคุยกับสวิตช์หรือเร้าเตอร์ให้รู้เรื่อง รวมถึงข้อดีข้อเสียของข้อมูลแบบมีโครงสร้าง (Structured Data)

---

## 📝 1. Structured Data vs Unstructured Data
*   **Unstructured Data (ข้อความดั้งเดิม):** การพิมพ์คำสั่ง (เช่น `show interfaces`) ผ่าน CLI ให้ผลลัพธ์ที่มนุษย์อ่านง่าย แต่คอมพิวเตอร์อ่านยาก การจะดึงค่ามาใช้ต้องเขียนโค้ดตัดคำเอาเอง (Screen Scraping) ซึ่งพังง่ายมาก
*   **Structured Data (ข้อมูลที่มีโครงสร้าง):** เช่น JSON, XML, YAML เป็นรูปแบบที่เกิดมาเพื่อให้ซอฟต์แวร์คุยกันรู้เรื่อง มีกฎชัดเจน มีไลบรารีรองรับ และนำไปใช้กับภาษาโปรแกรมอะไรก็ได้

**การขูดหน้าจอ (Screen Scraping):** คือเทคนิคยุคเก่าที่เราใช้ SSH จำลองพฤติกรรมคนพิมพ์คำสั่ง แล้วเอา String มาตัดคำเอง เป็นวิธีที่เปลืองเวลา เปราะบาง และอาจทำให้ Router แฮงก์ได้ อุปกรณ์ยุคใหม่จึงเปลี่ยนมาบังคับคายผลลัพธ์เป็น API / Structured Data หมดแล้ว

---

## 📝 2. รูปแบบข้อมูลแบบข้อความ (Text-Based Data Formats)
ข้อดีของรูปแบบที่เป็นตัวอักษรคือ มนุษย์ใช้ Notepad เปิดอ่านแก้ไขได้ง่าย และมีเครื่องมือรองรับเพียบ แต่ข้อเสียคือมี Overhead หรือกินพื้นที่แบนด์วิดท์เยอะกว่า Binary เล็กน้อย เพราะต้องพ่วงตัวอักษรที่เป็นโครงสร้าง (เช่น ปีกกา, แท็กเปิดปิด) ไปด้วย

**กระบวนการแปลงข้อมูลเพื่อรับ/ส่ง (Serialization & Deserialization):**
1.  **ขาเข้า (Decode & Deserialize):** เมื่อรับข้อมูล API มาเป็นเลขฐานสอง (0, 1) สายแลนจะถอดรหัส (Decode) เป็น String ยาวๆ ก่อน จากนั้นเราต้อง **Deserialize** เปลี่ยน String นั้นให้กลายเป็น Dictionary/List ใน Python ถึงจะนำไปบวกเลขต่อได้
2.  **ขาออก (Serialize & Encode):** เมื่อทำข้อมูลเสร็จ ต้อง **Serialize** เปลี่ยน Python Dictionary เป็น String (เช่น JSON) ก่อน แล้วค่อยเข้ารหัสเป็น 0, 1 ส่งออกไป

## 📝 3. เจาะลึกแต่ละ Data Formats

### 3.1 YAML (ยามล)
*   **จุดเด่น:** อ่านง่ายที่สุดสำหรับมนุษย์ (Human-friendly) ใช้กันแพร่หลายในเครื่องมือ Automation อย่าง Ansible
*   **โครงสร้าง:** ไม่ใช้ปีกกา แต่ใช้การขีดหน้าบรรทัด `-` (สำหรับ List) และโคลอน `:` (สำหรับ Dictionary คีย์-ค่า)
*   **ความฉลาด (Type Inference):** เดาให้อัตโนมัติว่าคำว่า `true` คือค่า Boolean และ `7700` คือตัวเลข
*   **การใช้งานใน Python:** ติดตั้งไลบรารี `pyyaml` และรัน `yaml.load(f)` จะได้ผลลัพธ์เป็น Python Dictionary

### 3.2 XML (Extensible Markup Language)
*   **จุดเด่น:** เก่าแก่แต่เก๋าเกม! เป็นโครงสร้างแบบต้นไม้ (Hierarchical Tree) ปัจจุบันถูกใช้อย่างหนักในโปรโตคอล **NETCONF** สำหรับจัดการอุปกรณ์เครือข่าย
*   **โครงสร้าง:** มี Root Tag อันเดียวครอบทั้งหมด มี Parent, Children และ Siblings
*   **Namespaces:** ป้องกันการตั้งชื่อแท็กซ้ำกันในระบบใหญ่
*   **การค้นหา (XPath):** เครื่องมือทรงพลังสำหรับการชี้พิกัดใน XML (เช่น หาว่า model ของสวิตช์ sw01 คืออะไร ผ่านคำสั่ง `tree.find("./device[@name='sw01']/model")`)

### 3.3 JSON (JavaScript Object Notation)
*   **จุดเด่น:** เป็น "แชมป์เปี้ยนตัวจริง" ของโลก API สมัยใหม่ เบากว่า XML มาก และทำงานคู่กับ HTTP (REST API) ได้ดีที่สุด
*   **โครงสร้าง:** เป็นสับเซตของ YAML แต่เข้มงวดกว่า บังคับใช้ปีกกา `{}` (Object/Dict) และวงเล็บเหลี่ยม `[]` (Array/List)
*   **การใช้งานใน Python:** โมดูล `json` เป็นของติดตัว Python มาแต่กำเนิด รันคำสั่ง `json.loads(text)` เพื่อแปลงเป็น Dictionary และ `json.dumps(dict)` เพื่อแปลงกลับเป็นข้อความ JSON

## 🔗 4. ความเชื่อมโยงกับโปรเจกต์ MyNetMate (AI Co-pilot)

ระบบ Architecture ของ **MyNetMate** ถูกออกแบบมาล้อตาม Best Practice ของบทนี้ทุกประการครับ:

*   **เปลี่ยน CLI เป็น JSON ด้วย TextFSM:** เราไม่ทำ Screen scraping! เราใช้ TextFSM แปลงผลลัพธ์ดั้งเดิมจาก Netmiko ให้กลายเป็น JSON เสมอ
*   **FastAPI = ราชาแห่ง JSON:** Backend ของเราทำงานด้วย JSON อัตโนมัติ (Serialize/Deserialize ให้ฟรี) ทำให้เราดึงข้อมูลจาก Database ส่งให้ React หน้าเว็บได้อย่างลื่นไหล
*   **Gemini AI พูดภาษา JSON:** แทนที่จะคุยกับ AI เป็นข้อความยาวๆ เราส่งโครงสร้าง Topology แบบ JSON เข้าไปใน Prompt ให้ AI วิเคราะห์ และรับคำตอบกลับมาเป็น JSON เสมอเพื่อนำไปประมวลผลต่อ (นี่คือการประยุกต์ใช้ Data Format อย่างฉลาด)

## 📌 5. Key Takeaways (สรุปแผนการลงมือทำ)

1.  **JSON คือเพื่อนแท้:** ในโค้ด FastAPI ของเรา ทุกๆ Endpoint (เส้นทาง API) ต้องคุยกันด้วย JSON เท่านั้น
2.  **ให้ Python ทำงานหนักแทน:** ทุกครั้งที่รับข้อมูลจาก Netmiko หรือ Database ให้แปลงมันเป็น Python Dictionary ก่อนเสมอ อย่าพยายามใช้ Regex ไปนั่งตัด String ดิบๆ
3.  **สั่งให้ AI ตอบเป็น JSON:** เวลาสร้าง Prompt ให้ Gemini อย่าลืมระบุคำสั่งบังคับว่า "ให้ตอบกลับเป็นโครงสร้าง JSON ตามรูปแบบดังต่อไปนี้เท่านั้น" เพื่อที่เราจะได้เอาไปทำ `json.loads()` และใช้คำสั่ง `if/else` ต่อได้ทันที
