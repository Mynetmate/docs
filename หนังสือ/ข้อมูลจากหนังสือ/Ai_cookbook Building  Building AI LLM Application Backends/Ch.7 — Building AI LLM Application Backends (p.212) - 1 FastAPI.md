**บทที่ 7: การสร้างระบบหลังบ้าน (Backend) สำหรับแอปพลิเคชัน AI**

ในยุคแรกเริ่มของอินเทอร์เน็ต แอปพลิเคชันเว็บไซต์มักจะถูกสร้างแบบรวบตึงเป็นก้อนเดียว (Monolithic) คือเอาทั้งหน้าตาเว็บ (HTML/CSS/JS) ไปปะปนกับโค้ดตรรกะการทำงาน (Logic) แต่ในปัจจุบัน แอปพลิเคชันส่วนใหญ่ได้ถูกจับแยกส่วนประกอบหลักออกเป็น 2 ฝั่งอย่างชัดเจน คือ **Frontend (หน้าบ้าน)** และ **Backend (หลังบ้าน)**

สาเหตุที่ต้องแยก 2 ส่วนนี้ออกจากกัน มี 3 ข้อหลักๆ คือ:

1. **ความเชี่ยวชาญเฉพาะด้าน (Specialization):** นักพัฒนาหน้าบ้านจะได้โฟกัสเรื่องประสบการณ์ผู้ใช้ (UX/UI) ไปเลย ส่วนคนทำหลังบ้านก็โฟกัสเรื่องตรรกะและจัดการข้อมูลเต็มที่
2. **การขยายระบบ (Scalability):** เวลาเราจะอัปเดตระบบ เราแก้โค้ดแค่ฝั่งใดฝั่งหนึ่งได้โดยไม่กระทบอีกฝั่ง ทำให้ระบบพังยากขึ้นและขยายสเกลได้ง่ายกว่า
3. **ความปลอดภัย (Security):** ข้อมูลที่มีความอ่อนไหวสูง (เช่น รหัสผ่าน, API Key) จะถูกเก็บซ่อนไว้ในหลังบ้าน ทำให้ปลอดภัยจากการถูกโจมตี

ผู้เขียนเปรียบเทียบให้เห็นภาพชัดเจนว่า ระบบพวกนี้เหมือน **"ร้านอาหาร"**

- **Frontend (หน้าบ้าน)** ก็เหมือน **พื้นที่โซนโต๊ะอาหาร** ที่ลูกค้านั่งดูเมนู สั่งอาหาร และนั่งทาน (เน้นสวยงาม ใช้งานง่าย)
- **Backend (หลังบ้าน)** ก็เหมือน **ห้องครัว** ที่ซึ่งความวุ่นวายและการเตรียมวัตถุดิบเกิดขึ้นลับหลังลูกค้า อาหารจะถูกปรุงที่นี่ก่อนจะส่งไปเสิร์ฟให้ลูกค้าที่โต๊ะ ทั้งสองฝั่งใช้ทักษะที่ต่างกัน แต่ต้องทำงานร่วมกันเพื่อให้ลูกค้าได้กินอาหารจานเด็ด

ผู้เขียนอธิบายต่อว่า ในบทก่อนๆ เขาใช้เครื่องมืออย่าง Streamlit สร้างแอปพลิเคชัน (ซึ่งมันรวบเอาหน้าบ้านกับหลังบ้านไว้ด้วยกัน) แต่มันมีข้อจำกัด หากเราอยากจะใช้ **Database (ฐานข้อมูล)** เพื่อเก็บข้อมูล หรืออยากขยายระบบ เราจำเป็นต้องสร้าง Backend หรือ API Server แยกออกมาต่างหาก

ในบทนี้จึงเป็นการสอนสร้าง Web Backend ด้วย **FastAPI** เพื่อให้ AI คอยตอบคำถามเกี่ยวกับ Network อย่างชาญฉลาด โดยจะค่อยๆ สร้างระบบต่อเนื่องกันไปตามลำดับ (ต่างจากบทอื่นที่แต่ละหัวข้อแยกกัน) ประกอบด้วย:

1. สร้าง API พื้นฐาน
2. เพิ่มบริบทของอุปกรณ์เครือข่าย (Device Context)
3. เชื่อมต่อระบบฐานข้อมูลเพื่อจัดเก็บข้อมูล
4. สร้างหน้าเว็บโต้ตอบแบบง่ายๆ
5. นำแอปพลิเคชันแพ็กขึ้น Docker

**💡 อธิบายและขยายความ (Explanation):**

หัวข้อนี้เป็นการปูพื้นฐาน **"สถาปัตยกรรมซอฟต์แวร์ (Software Architecture)"** สมัยใหม่ครับ การที่ผู้เขียนยกตัวอย่างร้านอาหาร เป็นการอธิบายคอนเซปต์ของ **API (Application Programming Interface)** ไปในตัว เพราะ API ก็เปรียบเสมือน "พนักงานเสิร์ฟ" ที่คอยรับออเดอร์จากโต๊ะอาหาร (Frontend) เดินเอาไปส่งให้พ่อครัว (Backend) และเมื่ออาหารเสร็จ พนักงานเสิร์ฟก็จะเดินถืออาหารมาวางให้ที่โต๊ะ

การทำแอปฯ AI ต้องระวังเรื่อง Security มากที่สุด เพราะถ้า API Key ของ AI (เช่น OpenAI หรือ Gemini) หลุดไปให้คนอื่นเห็น เราอาจจะโดนเรียกเก็บเงินบิลล์ค่าใช้งานหลักแสนได้เลย! ดังนั้นโค้ดส่วนที่คุยกับ AI จึงต้องซ่อนไว้ใน "ห้องครัว" เสมอ

1. **การแยก Frontend / Backend:** โปรเจกต์เราไม่ได้ทำแบบรวบตึง เรามีการแยก **FastAPI เป็นห้องครัว (Backend)** และมีการใช้ **PostgreSQL เป็นตู้เย็นเก็บวัตถุดิบ (Database)**
2. **ความปลอดภัยของระบบ:** กุญแจลับ `GEMINI_API_KEY` รวมถึงรหัสผ่านเข้าอุปกรณ์ Cisco/MikroTik ของเรา จะถูกเก็บซ่อนไว้อย่างปลอดภัยในฝั่ง FastAPI ลูกค้าที่เข้าใช้งานหน้าเว็บ (Frontend) จะไม่มีทางมองเห็นรหัสพวกนี้เด็ดขาด
3. **การแบ่งทีมทำงาน:** ด้วยโครงสร้างแบบนี้ เพื่อนในกลุ่มคุณสามารถแบ่งงานกันทำได้ชัดเจน คนนึงทำหน้าตาเว็บให้สวย (Frontend) อีกคนมุ่งไปที่การเขียน Python คุยกับ Network และ AI (Backend)
